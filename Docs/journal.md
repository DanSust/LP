# Журнал Made4Love: настройка и эксплуатация

`/journal` — редакционный журнал Made4Love. Это не новостная лента и не
агрегатор: материалы пишутся под задачу сервиса (отношения, свидания, города,
события), а чужие публикации используются только как повод и источник фактов.

Главные правила:

- AI может подготовить черновик, но **никогда не публикует** материал сам.
- Публикация возможна только после ручной проверки фактов и атрибуции.
- Текст источника не копируется: сервер считает пересечение и блокирует
  публикацию выше заданного порога.
- У каждого материала с источником есть название источника и ссылка на
  первоисточник; ссылка выводится с `rel="nofollow noopener noreferrer"`.
- Чужие изображения не загружаются автоматически. Картинка публикуется только
  после подтверждения прав.

## 0. Архитектура

Журнал разделён на два сервиса:

| Сервис | Порт | Ответственность |
| --- | --- | --- |
| `LP.Server` | 7010 | публичное чтение: `/Journal/public`, `/Journal/public/{slug}`, `/Journal/sitemap.xml` |
| `LP.Journal` | 7020 | админ-API, обход источников, AI-черновики, публикация |

`LP.Journal` — самостоятельный проект в решении (`LP.Journal/LP.Journal.csproj`).
Он запускается отдельно от `LP.Server` и использует общие сущности из `LP.Entity`.
Краулер работает как `BackgroundService` внутри `LP.Journal` и создаёт только
черновики: автопубликации нет.

## 1. Миграция базы

Автоматических миграций нет. Перед запуском новой версии примените миграции
вручную (startup-проект — `LP.Journal`, чтобы использовалась его конфигурация):

```powershell
dotnet ef database update --project LP.Entity --startup-project LP.Journal
```

- `20261112193104_AddJournalMvp` создаёт таблицу `NewsItems`.
- `20261113043402_AddJournalSources` создаёт `JournalSources` и добавляет в
  `NewsItems` поля `SourceId` и `ExternalId` с уникальным индексом
  `(SourceId, ExternalId)` (фильтр `SourceId IS NOT NULL AND ExternalId IS NOT NULL`,
  чтобы удаление источника не конфликтовало с чужими `ExternalId`).

Существующие данные не затрагиваются.

## 2. Конфигурация

Секция `Journal` в `LP.Journal/appsettings.json` / переменных окружения:

```json
"Journal": {
  "AdminKey": "",
  "SiteBaseUrl": "https://made4love.ru",
  "AiEnabled": false,
  "AiBaseUrl": "https://api.openai.com/v1",
  "AiApiKey": "",
  "AiModel": "",
  "MaxSimilarityPercent": 20,
  "CrawlEnabled": true,
  "CrawlCheckIntervalMinutes": 15,
  "MaxItemsPerSource": 10,
  "MaxDraftsPerRun": 30,
  "RequestDelayMilliseconds": 1000
}
```

- `AdminKey` — ключ админ-API и веб-админки. Пустое значение означает fallback
  на `Events:AdminKey`. Если оба ключа пусты, админ-API отвечает `503`.
- `SiteBaseUrl` — база для абсолютных ссылок в `/Journal/sitemap.xml`.
  Если пусто, используется `Events:SiteBaseUrl`.
- `AiEnabled` — глобальный выключатель AI-черновиков.
- `AiBaseUrl` — base URL OpenAI-совместимого API (OpenAI, OpenRouter, DeepSeek,
  Yandex Cloud и т.п.). Запрос идёт на `{AiBaseUrl}/chat/completions`.
- `AiApiKey`, `AiModel` — ключ и имя модели.
- `MaxSimilarityPercent` — допустимое пересечение черновика с источником.
  По умолчанию 20%. Публикация выше порога блокируется.
- `CrawlEnabled` — включает периодический обход источников.
- `CrawlCheckIntervalMinutes` — как часто краулер проверяет, какие источники
  пора обойти. Минимум 1 минута; у каждого источника свой
  `SyncIntervalMinutes` (минимум 15 минут).
- `MaxItemsPerSource` — глобальный лимит материалов за один проход источника.
- `MaxDraftsPerRun` — лимит новых черновиков за один запуск краулера.
- `RequestDelayMilliseconds` — пауза между загрузками страниц, чтобы не
  нагружать чужие сайты.

Ключи задавайте через переменные окружения, а не в репозитории:

```powershell
$env:Journal__AdminKey = "длинный-случайный-ключ"
$env:Journal__AiEnabled = "true"
$env:Journal__AiApiKey = "<ключ провайдера>"
$env:Journal__AiBaseUrl = "https://openrouter.ai/api/v1"
$env:Journal__AiModel = "<модель>"
```

Без AI-ключа журнал полностью работоспособен: краулер создаёт заготовки с
метаданными источника и пустым телом, редактор пишет текст вручную.

## 3. Пайплайн

### Обход источников

```
источник (RSS/Atom или HTML-страница)
   → читатель источника (RssJournalSourceReader / HtmlJournalSourceReader)
   → дедупликация по (SourceId, ExternalId) и SourceUrl
   → загрузка статьи и извлечение текста (ArticleFetcher)
   → фильтр по ключевым словам источника (DefaultTags)
   → AI-черновик в голосе Made4Love (опционально)
   → проверка пересечения с оригиналом (shingle-5)
   → черновик Draft в БД
   → ручная редактура и чек-лист
   → публикация
```

Краулер:

- обходит только включённые источники (`IsEnabled`);
- соблюдает `SyncIntervalMinutes` источника и лимиты за проход;
- пропускает уже известные материалы;
- пропускает статьи без ключевых слов источника (`DefaultTags` — слова через
  запятую; достаточно совпадения хотя бы одного слова в заголовке, описании
  или тексте; пустое поле означает «все статьи»);
- никогда не публикует автоматически;
- обновляет `LastSyncAt`, `LastSyncStatus`, `LastSyncError`;
- при ошибке источника продолжает работу и пишет ошибку в источник.

### Типы источников

- `Rss` — RSS 2.0, Atom, RDF. Заголовок, ссылка, дата, описание и категории
  ищутся по распространённым именам тегов.
- `Html` — HTML-страница со списком материалов. Краулер берёт ссылки того же
  сайта, отбрасывает рубрики, теги, пагинацию, служебные страницы и короткие
  подписи вроде «Читать далее». Необязательный `IncludePattern` (regex)
  ограничивает обход нужными разделами.

### Где брать источники

Список источников **не формируется автоматически**. Таблица `JournalSources`
изначально пуста: источник добавляет редакция — через `/admin/journal` →
«Источники», через `POST /Journal/admin/sources` или напрямую в БД. Автопоиска
и автоподписки в журнале нет: источник — это осознанное редакционное решение,
а не результат обхода интернета.

Где искать кандидатов:

1. **RSS-иконка на самом сайте** — у большинства изданий есть `/rss`, `/feed`
   или `/export/rss/...`.
2. **RSS-каталоги** (rss.ru, 2rss и подобные) — для первичного поиска по теме.
3. **Google News RSS по запросу** — тематический мониторинг без парсинга
   выдачи:
   `https://news.google.com/rss/search?q=психология+отношений&hl=ru&gl=RU&ceid=RU:ru`
4. **RSSHub** (self-hosted) — если нужны Telegram-каналы, VK и соцсети, у
   которых нет собственного RSS.
5. **HTML-источник** — для сайтов без RSS (городские афиши, локальные издания).
   Указывается страница **со списком** материалов, а не отдельная статья;
   `IncludePattern` при необходимости ограничивает раздел.

Проверенные фиды (доступность проверена 13.11.2026; её нужно периодически
перепроверять кнопкой «Проверить»):

| Источник | URL | Материалов в фиде |
| --- | --- | --- |
| Лента.ру | `https://lenta.ru/rss/news` | 200 |
| РИА Новости | `https://ria.ru/export/rss2/archive/index.xml` | 92 |
| ТАСС | `https://tass.ru/rss/v2.xml` | 98 |
| Афиша Daily | `https://daily.afisha.ru/rss/` | 5 |
| mos.ru | `https://www.mos.ru/rss` | 10 |
| Вечерняя Москва | `https://vm.ru/rss` | 60 |
| Сноб | `https://snob.ru/rss/` | 50 |

Это стартовый набор для проверки механики, а не рекомендация включить всё
сразу. Под тематику Made4Love (отношения, свидания, города, события) ищите
психологические и семейные медиа, городские афиши и локальные издания.

Критерии отбора:

- тематика совпадает с журналом, а не «всё подряд»;
- есть публичный RSS или стабильная HTML-страница списка;
- приемлемая частота публикаций, чтобы не тонуть в черновиках;
- редакция готова указывать источник и ссылку и **не копировать** чужие
  тексты и изображения;
- правовая политика сайта не запрещает использование материалов как повода
  (текст всё равно пишется заново, картинки не забираются автоматически).

Порядок подключения:

1. Вкладка «Источники» → «Добавить источник»: название, тип, URL, тема/город,
   ключевые слова через запятую (по ним отбираются статьи), интервал и лимит
   материалов.
2. **«Проверить»** (`POST /Journal/admin/sources/{id}/test`) — разовый обход
   без создания черновиков; видно, парсится ли фид и какие материалы нашлись.
3. **«Обойти»** (`POST /Journal/admin/sources/{id}/sync`) — создать черновики
   сейчас; **«Обойти все»** (`POST /Journal/admin/sources/sync`) — по всем
   включённым источникам.
4. Дальше `JournalCrawlBackgroundService` обходит источники по их
   `SyncIntervalMinutes`; автопубликации нет.

### Загрузка источника

`ArticleFetcher`:

- принимает только публичные `http(s)`-адреса;
- блокирует `localhost`, `.local`, loopback и частные диапазоны IP;
- ограничивает страницу 2 МБ, извлечённый текст — 16 000 символов;
- вырезает `script`, `style`, `nav`, `header`, `footer`, `aside`;
- извлекает `og:title`, `og:site_name`, дату публикации и основной текст;
- **не забирает изображения**.

Если страница отдаёт контент только через JavaScript, загрузка завершится
понятной ошибкой — материал нужно создать вручную.

### Форматирование текста материала

В теле материала (`Body`) разрешено безопасное HTML-форматирование:
`b`, `strong`, `i`, `em`, `u`, `s`, `strike`, `p`, `br`, `ul`, `ol`, `li`,
`blockquote`, `h2`–`h6`, `code`, `pre` и `a[href]`. В админке над полем текста
есть кнопки вставки тегов; абзацы разделяются пустой строкой.

Сервер (`JournalTextCleaner.NormalizeBody`) удаляет все остальные теги,
атрибуты и скрипты, проверяет ссылки (только `http(s)`, `mailto` и пути внутри
сайта) и экранирует остальной HTML. Публичная страница выводит текст через
`[innerHTML]` — Angular дополнительно санитизует разметку. Для SEO и описаний
используется версия без тегов.

### AI-генератор

Реализация `OpenAiNewsDraftGenerator` работает с любым OpenAI-совместимым
`/chat/completions`. Промпт требует:

- не копировать формулировки источника (максимум одна короткая цитата);
- не выдумывать факты, цифры, имена и даты;
- писать 400–700 слов, 4–7 абзацев, без HTML и markdown;
- вернуть строго JSON `{ "title", "summary", "body" }`.

В БД сохраняются `AiGenerated`, `AiModel`, `PromptVersion`
(текущая версия — `journal-draft-v1`) и `SimilarityPercent`.

### Проверка пересечения

`NewsSimilarityService` считает долю shingle-5 (пять слов подряд) черновика,
которые встречаются в исходном тексте. Это дешёвая проверка на дословное
копирование, а не полноценный антиплагиат. Порог задаётся
`Journal:MaxSimilarityPercent`.

## 4. Правила публикации

Сервер не публикует материал, если:

- нет заголовка или текста;
- не отмечено «факты проверены» (`FactsChecked`);
- не отмечено «источник указан / материал оригинальный» (`AttributionChecked`);
- указана ссылка на источник без названия источника;
- указана картинка, но не подтверждены права (`ImageRightsChecked`);
- материал помечен как AI-черновик, но пересечение не проверено
  (`SimilarityPercent` = `null`);
- пересечение с источником выше `MaxSimilarityPercent`.

Материал без источника допустим, если он полностью оригинальный. Для него
достаточно `FactsChecked` и `AttributionChecked`.

Опубликованный материал нельзя удалить: сначала нужно снять его с публикации.
Это защищает внешние ссылки и sitemap от «мёртвых» URL.

## 5. Админка

Веб-админка: `/admin/journal` (закрыта от индексации, ключ хранится в
`sessionStorage` вкладки). Из админки событий есть переход «Журнал», из журнала —
«События». В админке две вкладки: «Материалы» и «Источники».

Порядок работы с материалами:

1. Введите `AdminKey`.
2. Блок «Черновик из ссылки»: вставьте URL, при необходимости укажите тему,
   город и пожелания редактора. Кнопка активна только при настроенном AI.
3. Проверьте заголовок, текст и пересечение с источником.
4. Заполните атрибуцию: название источника, ссылка, оригинальный заголовок,
   дата публикации.
5. Отметьте чек-лист: факты, атрибуция, права на изображение.
6. «Сохранить», затем «Опубликовать».
7. «Снять с публикации» возвращает материал в черновики.
8. «Отклонить» скрывает материал и сохраняет причину в `RejectionReason`.

Порядок работы с источниками:

1. Вкладка «Источники» → «Добавить источник».
2. Укажите название, тип (`RSS / Atom` или `HTML-страница`) и публичный URL.
3. При необходимости задайте тему, город, теги, интервал и лимит материалов.
4. «Проверить» — разовый обход без сохранения черновиков; покажет найденные
   материалы и ошибку, если источник недоступен.
5. «Обойти» — создать черновики из этого источника сейчас.
6. «Обойти все» — пройти по всем включённым источникам.

Периодический обход выполняет `JournalCrawlBackgroundService`; он запускается
вместе с `LP.Journal` и работает без открытой админки.

## 6. API

Публичное чтение остаётся в `LP.Server`:

| Метод | Маршрут | Доступ |
| --- | --- | --- |
| `GET` | `/Journal/public?topic=&page=&pageSize=` | анонимно |
| `GET` | `/Journal/public/{slug}` | анонимно, `404` для черновиков |
| `GET` | `/Journal/sitemap.xml` | анонимно |

Админ-API живёт в `LP.Journal` (порт 7020) и защищён `X-Admin-Key`:

```
GET    /Journal/admin/config
GET    /Journal/admin/items?status=Draft|Published|Rejected|Archived|all
GET    /Journal/admin/items/{id}
POST   /Journal/admin/items
PUT    /Journal/admin/items/{id}
POST   /Journal/admin/items/{id}/publish
POST   /Journal/admin/items/{id}/unpublish
POST   /Journal/admin/items/{id}/reject
DELETE /Journal/admin/items/{id}
DELETE /Journal/admin/items              # тело: массив GUID выбранных материалов
POST   /Journal/admin/draft-from-url

GET    /Journal/admin/sources
GET    /Journal/admin/sources/{id}
POST   /Journal/admin/sources
PUT    /Journal/admin/sources/{id}
DELETE /Journal/admin/sources/{id}
POST   /Journal/admin/sources/{id}/test
POST   /Journal/admin/sources/{id}/sync
POST   /Journal/admin/sources/sync
```

`draft-from-url` ничего не сохраняет: он возвращает готовый черновик, источник
и процент пересечения, а редактор решает, сохранять ли материал.

Одиночный `DELETE /items/{id}` не удаляет опубликованные материалы. Массовый
`DELETE /items` с массивом GUID удаляет выбранные записи независимо от статуса
(в том числе опубликованные) и возвращает `{ "deleted": <число> }` — он используется
в админке для удаления отмеченных чекбоксами материалов.

Снаружи через nginx админ-API доступен по тому же пути `/api/Journal/admin/...`:
маршрут проксируется на `journal:7020`, остальной `/api/` — на `LP.Server`.

## 7. SEO и маршруты

- `/journal` — список опубликованных материалов.
- `/journal/:slug` — статья.
- У обоих маршрутов `dynamicSeo: true`: мета-теги, canonical, Open Graph и
  JSON-LD (`CollectionPage`, `NewsArticle`) выставляет клиент после загрузки.
- `/journal` имеет статическую SEO-оболочку (`generate-seo-pages.mjs`).
- `/journal-sitemap.xml` проксируется nginx на `/Journal/sitemap.xml` и содержит
  только опубликованные материалы.
- Canonical ведёт на свою страницу, а не на источник.
- В JSON-LD статьи передаются `author`, `datePublished`, `dateModified`,
  `isBasedOn` и `citation` (при наличии источника).
- `/admin` закрыт в `robots.txt` и получает `X-Robots-Tag: noindex, nofollow`.

### Ограничение SPA-индексации

Статьи рендерятся на клиенте. Google и Яндекс выполняют JavaScript, но для
большого архива в будущем потребуется SSR или пререндер. Для MVP это осознанное
ограничение.

## 8. Проверка после деплоя

```powershell
# Публичный список
curl https://made4love.ru/api/Journal/public

# Sitemap журнала
curl https://made4love.ru/journal-sitemap.xml

# Админ-API с ключом (nginx → LP.Journal:7020)
curl -H "X-Admin-Key: <ключ>" https://made4love.ru/api/Journal/admin/config
```

Если админ-API отвечает `503`, ключ не задан. Если `401` — ключ не совпал.
Если `502`, проверьте, что `LP.Journal` запущен на порту 7020.

Полный smoke-тест локально:

1. Запустить `LP.Journal` (`dotnet run --project LP.Journal`) и `LP.Server`.
2. `GET http://localhost:7020/health` → `200`.
3. `GET /Journal/admin/config` без ключа → `401`; с ключом → `200`.
4. Создать источник RSS → `201`; «Проверить» → список материалов.
5. «Обойти» → черновики создаются, повторный обход их не дублирует.
6. Создать черновик вручную → `201`, статус `Draft`.
7. Публикация без чек-листа → `400` с понятной причиной.
8. Заполнить чек-лист и опубликовать → `200`.
9. `GET /Journal/public` и `/Journal/public/{slug}` → материал виден.
10. `/Journal/sitemap.xml` содержит slug.
11. `unpublish` → материал исчезает из публичного API (`404`).
12. `reject` → статус `Rejected`; `delete` → `204`.
13. `draft-from-url` с `localhost` → ошибка про публичную ссылку.
14. Удалить тестовые данные.

## 9. Ограничения MVP

- Нет очереди редактора и назначения авторов.
- Нет тематических и городских страниц журнала — только общий список.
- Нет профилей авторов и рассылки.
- Антиплагиат — только shingle-5, без внешних сервисов.
- Изображения не загружаются автоматически; права подтверждаются вручную.
- HTML-источники разбираются регулярными выражениями, без полноценного
